# AGENTS.md

Barangay document request system. Django 6 app (app `brgy`) on Python 3.13, Windows. Virtualenv lives at repo root: `venv\` (activate with `.\venv\Scripts\Activate.ps1`).

## Critical: no Django ORM

All persistence is **Cloud Firestore** via the Firebase Admin SDK. `DATABASES` uses `django.db.backends.dummy` and `settings.py` says so. Consequences:

- **Never run `makemigrations` or `migrate`.** The `brgy/migrations/` files are vestigial from the old SQLite version; `models.py` classes are dict-backed wrappers, not ORM models.
- All data access goes through `brgy/firestore_db.py` (collections: `barangays`, `users`, `document_types`, `document_requests`, `document_request_items`, `notifications`, `activity_logs`).
- `list_docs()` filters and sorts in Python using single-field equality only, to **avoid composite Firestore indexes**. Keep new queries in this pattern — do not add multi-field Firestore filters.

## Setup

- `my_project/firebase_credentials.json` (Firebase service account) is required locally. It is currently **not** gitignored and sits untracked — do not commit it. `settings.py` falls back to Application Default Credentials / `FIRESTORE_EMULATOR_HOST` if the file is missing.
- Password hashing uses Django's `make_password`/`check_password` even though users live in Firestore.
- `TIME_ZONE` is `Asia/Manila`; timestamps are stored UTC-aware via `firestore_db.utcnow()` / `_to_firestore`.

## Commands (run from `my_project/`)

- Smoke check: `python manage.py check` (works without Firestore access)
- Dev server: `python manage.py runserver`
- Seed all roles: `python manage.py seed_test_users` — creates admin/staff/resident/resident_pending plus a test barangay and document types. Default password `Test@123`.
- `python manage.py update_theme_colors` — one-off: migrates legacy blue theme to emerald green.

## Auth

Custom Firestore-backed auth: `brgy.auth.FirestoreBackend`, `brgy.middleware.FirestoreAuthMiddleware` replaces Django's `AuthenticationMiddleware`, sessions are signed cookies. Roles: `admin`, `staff`, `resident`; residents have `verification_status` of pending/approved/rejected.

## Gotchas

- Request numbers are generated by `next_request_number()` as `BRG-YYYYMMDD-NNNN`.
- Generated documents use `docxtpl` with per-document-type `.docx` templates uploaded to `media/document_templates`.
- Stale ad-hoc scripts in `my_project/` (`create_test_user.py`, `debug_firestore.py`, `fix_is_active.py`) are superseded by the `seed_test_users` command — prefer the command.
- No tests, no lint config, no CI. `brgy/tests.py` was deleted.
