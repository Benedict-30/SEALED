# AGENTS.md

Barangay document request system. Django 6.0 app (app `brgy`) on Python 3.13, Windows. Virtualenv lives at repo root: `venv\` — activate with `.\venv\Scripts\Activate.ps1`, then run commands from `my_project/`.

## Critical: no Django ORM

All persistence is **Cloud Firestore** via the Firebase Admin SDK. `DATABASES` uses `django.db.backends.dummy` (`my_project/settings.py`). Consequences:

- **Never run `makemigrations` or `migrate`.** There is no database backend and the `brgy/migrations/` folder was deleted (the old SQLite era is fully removed); `models.py` classes are dict-backed wrappers, not ORM models.
- All data access goes through `brgy/firestore_db.py` (collections: `barangays`, `users`, `document_types`, `document_requests`, `document_request_items`, `notifications`, `activity_logs`).
- `list_docs()` fetches everything and filters/sorts in Python using single-field equality only, to **avoid composite Firestore indexes**. Keep new queries in this pattern — do not add multi-field Firestore filters or `order_by` in `.where()`.

## Setup

- `my_project/firebase_credentials.json` (live Firebase service account) and `my_project/.env` are **git-ignored** (see `.gitignore`) and must never be committed. Treat `firebase_credentials.json` as a secret: never print/echo its contents. `settings.py` falls back to Application Default Credentials / `FIRESTORE_EMULATOR_HOST` if the file is missing.
- Password hashing uses Django's `make_password`/`check_password` even though users live in Firestore.
- `TIME_ZONE` is `Asia/Manila`; timestamps are stored UTC-aware via `firestore_db.utcnow()` / `_to_firestore`.
- Env overrides in `settings.py`: `DJANGO_SECRET_KEY`, `DJANGO_DEBUG`, `DJANGO_ALLOWED_HOSTS`.

## Commands (run from `my_project/`)

- Smoke check: `python manage.py check` (no Firestore connection needed)
- Dev server: `python manage.py runserver`
- Dependencies: `pip install -r requirements.txt` (requirements file lives in `my_project/`)
- Seed all roles: `python manage.py seed_test_users` — creates admin/staff/resident/resident_pending plus a test barangay and document types. Default password `Test@123` (`--password` to override).
- `python manage.py update_theme_colors` — one-off: migrates legacy blue theme `#4F46E5` to emerald green `#059669`.

## Auth

Custom Firestore-backed auth: `brgy.auth.FirestoreBackend`, `brgy.middleware.FirestoreAuthMiddleware` replaces Django's `AuthenticationMiddleware`; sessions are signed cookies. Roles: `admin`, `staff`, `resident`; residents have `verification_status` of pending/approved/rejected.

## Gotchas

- Request numbers are generated by `next_request_number()` as `BRG-YYYYMMDD-NNNN` — primarily a transactional per-day counter in the `counters` collection, falling back to scanning all `document_requests` if the transaction can't complete.
- Generated documents use `docxtpl`. Each document type has an uploaded `.docx` template stored under `media/document_templates/` (field `template_file`); `print_document` renders it **dynamically**: `detect_template_variables()` (`brgy/forms.py`) extracts every Jinja2 placeholder on upload, `canonicalize_variables()` translates secret tokens to canonical names, and the result is stored in `template_variables` on the `document_type`/`document_type_override` doc; `_build_template_context()` + `_resolve_template_context()` (`brgy/views.py`) auto-fill any placeholder from a flat resident/barangay/request/item/doc-type namespace (canonical names, `TEMPLATE_VAR_ALIASES`, secret tokens), so templates are NOT limited to fixed names.
- Secret placeholder tokens (`brgy/template_tokens.py`): each document type has a stable `template_salt` (random hex stored on create; legacy types fall back to their Firestore pk); `token_for()` mints deterministic 10-char tokens (`HMAC-SHA256(DJANGO_SECRET_KEY, salt:field)`, base32) per field. Staff sheets on the staff Templates pages map `token ↔ field` so templates can use scrambled names (e.g. `{{ aB3xQ9Zk }}` instead of `{{ resident_name }}`) — this is obfuscation of template semantics, not encryption. Both forms always resolve (`_inject_token_values()` puts the whole token sheet into the render context, since stored `template_variables` are canonical). `_sheet_variables()` prefers stored vars but falls back to live-detecting the template file, so legacy types (no stored `template_variables`) still get token sheets on staff + admin Templates pages. Date/age placeholders: `date_day/month/month_name/year/day_of_week` (issuance), `resident_birth_day/month/month_name/year` plus precise `resident_age` (via `_as_template_date()`/`_precise_age()`; blank when unparseable). Keep `KNOWN_CANONICAL_FIELDS` in sync with the render namespace.
- Verification is per-document: `mark_printed` mints a unique 12-char `verification_code` on each `document_request_item` (stable on re-print); `print_document` renders it via the `verification_code`/`verify_url` placeholders, which staff must place manually in the template (no auto-appended footer). The public `/verify/?code=` page accepts printed/ready/completed requests and legacy request-level codes.
- Stale ad-hoc scripts in `my_project/` (`create_test_user.py`, `debug_firestore.py`, `fix_is_active.py`) are superseded by the `seed_test_users` command — prefer the command.
- Offline suite: `python smoke_tests.py` (runs from `my_project/`, no Firestore connection needed). No lint config, no CI. `brgy/tests.py` was deleted.
