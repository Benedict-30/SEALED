# AGENTS.md

Barangay document request system. Django 6.0 app (app `brgy`) on Python 3.13, Windows. Virtualenv lives at repo root: `venv\` — activate with `.\venv\Scripts\Activate.ps1`, then run all commands from the repo root (where `manage.py` lives).

## Project layout

- Repo root = Django project root (`manage.py`).
- `config/` — Django settings package (`settings.py`, `urls.py`, `wsgi.py`, `asgi.py`).
- `brgy/` — the app. Views, forms, and URLs are split by role into packages that mirror `brgy/templates/brgy/<role>/`:
  - `brgy/views/` → `common.py`, `resident.py`, `staff.py`, `admin.py`
  - `brgy/forms/` → `auth.py`, `resident.py`, `staff.py`, `admin.py`
  - `brgy/urls/` → `common.py`, `resident.py`, `staff.py`, `admin.py`
  - Shared logic: `brgy/services.py` (notify, log_activity, staff_of_barangay, requests_for_barangay, `_*_or_404`, `_save_uploaded_file`, …) and `brgy/decorators.py` (`role_required`).
  - `brgy/views/__init__.py` and `brgy/forms/__init__.py` re-export everything, so `from . import views` / `from .forms import …` still work.
- `scripts/` — stale ad-hoc scripts (`create_test_user.py`, `debug_firestore.py`, `fix_is_active.py`). They are superseded by the `seed_test_users` command — prefer the command.
- `media/` — uploaded files (barangay logos, `.docx` templates, resident IDs).

## Critical: no Django ORM

All persistence is **Cloud Firestore** via the Firebase Admin SDK. `DATABASES` uses `django.db.backends.dummy` (`config/settings.py`). Consequences:

- **Never run `makemigrations` or `migrate`.** The `brgy/migrations/` files are vestigial from the old SQLite version; `models.py` classes are dict-backed wrappers, not ORM models.
- All data access goes through `brgy/firestore_db.py` (collections: `barangays`, `users`, `document_types`, `document_requests`, `document_request_items`, `notifications`, `activity_logs`).
- `list_docs()` fetches everything and filters/sorts in Python using single-field equality only, to **avoid composite Firestore indexes**. Keep new queries in this pattern — do not add multi-field Firestore filters or `order_by` in `.where()`.

## Setup

- `firebase_credentials.json` (live Firebase service account) lives at the repo root and is **gitignored** (never committed). Treat it as a secret: never print/echo its contents or commit a rotated copy. `settings.py` falls back to Application Default Credentials / `FIRESTORE_EMULATOR_HOST` if the file is missing.
- Password hashing uses Django's `make_password`/`check_password` even though users live in Firestore.
- `TIME_ZONE` is `Asia/Manila`; timestamps are stored UTC-aware via `firestore_db.utcnow()` / `_to_firestore`.
- Env overrides in `settings.py`: `DJANGO_SECRET_KEY`, `DJANGO_DEBUG`, `DJANGO_ALLOWED_HOSTS`.

## Commands (run from repo root)

- Smoke check: `python manage.py check` (no Firestore connection needed)
- Dev server: `python manage.py runserver`
- Dependencies: `pip install -r requirements.txt` (requirements file lives at the repo root)
- Seed all roles: `python manage.py seed_test_users` — creates admin/staff/resident/resident_pending plus a test barangay and document types. Default password `Test@123` (`--password` to override).
- `python manage.py update_theme_colors` — one-off: migrates legacy blue theme `#4F46E5` to emerald green `#059669`.

## Auth

Custom Firestore-backed auth: `brgy.auth.FirestoreBackend`, `brgy.middleware.FirestoreAuthMiddleware` replaces Django's `AuthenticationMiddleware`; sessions are signed cookies. Roles: `admin`, `staff`, `resident`; residents have `verification_status` of pending/approved/rejected.

## Gotchas

- Request numbers are generated by `next_request_number()` as `BRG-YYYYMMDD-NNNN` — computed by scanning all `document_requests`, not a stored counter.
- Generated documents use `docxtpl`. Each document type has an uploaded `.docx` template stored under `media/document_templates/` (field `template_file`); `print_document` (`brgy/views/staff.py`) renders it with context keys `resident_name`, `resident_address`, `purpose`, `date_today`, `barangay_name`, `chairman_name`, `request_number`. Templates use these exact Jinja2-style placeholder names.
- No tests, no lint config, no CI. `brgy/tests.py` was deleted.
